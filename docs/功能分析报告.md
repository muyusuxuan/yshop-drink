# yshop-drink 项目功能分析报告

> 分析对象：本仓库（`muyusuxuan/yshop-drink`，源自 [guchengwuyue/yshop-drink](https://github.com/guchengwuyue/yshop-drink)）  
> 分析方式：对照源码、路由、Controller、SQL，不以官网宣传文案为准  
> 依赖安装与样式预览：按约定由本地完成，本报告不覆盖运行效果

---

## 1. 项目定位

这是一套 **饮品 / 轻餐点餐系统**（官方自称「意象点餐」），模仿肯德基式小程序：用户选店、选规格、下单、支付；后台管门店、商品、订单、会员、营销。

**开源版实际可跑通的主路径是「到店自取 + 外卖配送」**，不是完整堂食扫码系统。README 里的桌台扫码、云小票打印、充值、会员卡等，有一部分只在商业版或代码 TODO 里。

适合作为二次开发骨架：三端齐全、RBAC / 多租户脚手架完整，但业务语义全部绑定「门店点餐」。后续若改成软件兼职平台，需要换业务模型，而不是只改文案。

## 4. C 端小程序 / H5（`yshop-drink-uniapp-vue3`）

### 4.1 信息架构

底部 Tab：首页 · 点餐 · 订单 · 我的。

```
首页 ──自取/外卖──► 点餐（分类+SKU+购物车）──► 确认支付
                      │                         │ 选店 / 地址 / 券 / 备注
我的 ──卡券 / 积分 / 地址 / 资料 / 账单
订单 ──详情 / 确认收餐 / 退款
积分商城 ──列表 / 详情 / 确认兑换 / 积分订单
```

### 4.2 页面清单

**主包**

| 页面 | 做什么 |
|------|--------|
| `pages/index/index` | 轮播广告；自取 / 外卖入口；卡券数量；积分商城入口 |
| `pages/menu/menu` | 核心点餐：定位最近店、分类商品、规格弹窗、本地购物车、去结算 |
| `pages/order/order` | 餐饮订单列表（全部 / 待支付 / 进行中 / 已完成 / 退款） |
| `pages/mine/mine` | 会员信息、券 / 积分 / 余额、后台配置的「我的服务」 |

**结算分包 `pages-checkout`**

| 页面 | 做什么 |
|------|--------|
| `pay/pay` | 提交订单 + 统一支付（微信 / 余额 / H5 支付宝） |
| `remark/remark` | 订单备注（≤50 字 + 快捷语） |
| `packages/index` | 按门店和自取 / 外卖场景选券 |
| `shop/shop` | 门店列表、搜索、导航、电话、切店 |
| `cart/cart` | 独立购物车页（与菜单内弹层重复） |

**订单分包 `pages-order`**

| 页面 | 做什么 |
|------|--------|
| `orders/detail` | 取餐号、制作 / 配送步骤、金额、收餐、申请退款 |
| `orders/refund` | 整单退款（原因写死「协商一致」） |
| `orders/orders` | 与 Tab 订单几乎重复，**无入口** |

**用户分包 `pages-user`**

| 页面 | 做什么 |
|------|--------|
| `login/login` | 短信登录；小程序手机号快捷登录 |
| `address/*` | 地址列表 / 新增编辑，地图选点，外卖校验配送范围 |
| `coupons/coupons` | 我的券 / 可领券 / 兑换码 |
| `mine/userinfo` | 昵称、头像、性别、生日 |
| `mine/content` | CMS 协议 / 说明富文本 |
| `balance/bill` | 余额 / 积分流水 |
| `login/logout` | 清 token，**无入口** |

**积分分包 `pages-score`**

| 页面 | 做什么 |
|------|--------|
| `scoreproduct/list` | 积分商品瀑布流 |
| `scoreproduct/detail` | 详情 |
| `scoreproduct/confirm` | 选地址后兑换 |
| `scoreproduct/order` | 积分订单（待发货 / 待收货 / 已完成） |
| `scoreproduct/orderDetail` | 物流查询、确认收货 |

### 4.3 登录与支付

- **小程序**：冷启动 `userAuthSession`（`uni.login`）拿 openId；登录页支持短信 + `getPhoneNumber` 快捷登录。
- **H5 微信内**：公众号 OAuth（`snsapi_userinfo`）。
- **H5 / App**：短信验证码。
- **支付**：小程序 `uni.requestPayment`；H5 走 MWEB 或支付宝表单；余额 `paytype=yue`。
- **公众号 JSAPI 支付**：代码分支为空，`jweixin` 已引入未使用。

购物车存在 `uni.storage` 的 `cart`，不走独立购物车接口，下单时把 `productId[] / spec[] / number[]` 一次性提交。

### 4.4 C 端缺口（改项目时优先知道）

1. 无扫码桌台、无预约、无多人拼单。
2. 充值 API 在 `api/user.js`，个人中心余额不可点、无充值页。
3. 「我的服务」`type=menu` 指向未注册路由；`type=contact` 点击无效。
4. 小程序 AppId、公众号 AppId、App 微信 AppId 三处不一致，联调会踩坑。
5. 商品弹窗「可获积分:10」写死。

## 5. 管理后台（`yshop-drink-vue3`）

后台菜单由后端 `system_menu` 动态下发，前端按 `component` 懒加载 `src/views/**`。权限是标准 RBAC：`v-hasPermi` + 角色数据范围。

### 5.1 点餐业务

| 模块 | 路径 | 能力 |
|------|------|------|
| 首页看板 | `views/Home` | 会员数、订单数、金额、商品统计、公告 |
| 商品分类 | `mall/product/category` | CRUD |
| 门店商品 | `mall/product/storeProduct` | 单 / 多规格 SKU、上下架、素材图、按店筛选 |
| 规格模板 | `mall/shop/storeProductRule` | 规格名 + 属性值，供商品引用 |
| 评价 / 收藏 | `storeProductReply` / `storeProductRelation` | 回复评价、删收藏 |
| 门店 | `mall/store/shop` | 多店、地图选点、营业时间、外卖距离 / 起送 / 配送费、绑定分店管理员 |
| 轮播广告 | `mall/shop/ads` | 按店或全平台 |
| 我的服务 | `mall/shop/service` | 配置 C 端「我的」入口（页面 / 小程序 / 电话 / 内容） |
| 充值套餐 | `mall/shop/recharge` | 面值 / 售价（C 端入口缺失） |
| 订单 | `mall/order/storeOrder` | 外卖 / 自取筛选，出单、退款、确认付款、备注、删除 |
| 出餐工作台 | `storeOrder/work.vue` | 制作中订单卡片（后厨 / 前台大屏向） |
| 优惠券 | `mall/coupon` | 门槛、面额、发行量、限领、场景（自取 / 外卖 / 通用） |
| 会员 | `mall/member/user` | 渠道 Tab、改余额积分、账单、地址 |

### 5.2 积分、物流、支付、消息

- 积分商品 / 积分订单发货（`views/score`）
- 快递公司字典（`views/express`）
- 支付商户配置：微信 / 支付宝 appid、mchId（`views/pay/merchantDetails`）
- 微信模板 / 订阅消息（`views/message/wechatTemplate`）

### 5.3 微信生态（`views/mp`）

公众号账号、小程序账号、自定义菜单、永久素材、自动回复、图文草稿与发布、粉丝与标签、消息记录、用户增减统计。

### 5.4 系统与基础设施（芋道脚手架）

- 用户 / 角色 / 菜单 / 部门 / 岗位 / 字典
- 租户与租户套餐（SaaS）
- 短信 / 邮件 / 站内信 / 公告
- OAuth2 客户端与令牌、社交登录
- 登录日志 / 操作日志
- 文件、配置中心、代码生成、定时任务、Redis / Druid 监控

这些对「兼职平台后台」可直接复用，不必重写权限体系。

### 5.5 后台缺口

- 无桌位 / 区域 / 桌码管理页。
- 无独立收银机模块。
- `DiyEditor` 不存在，可视化装修未落地。
- 「打印」按钮实际是出单状态变更，未调 `printOrder`。
- 商品品牌 API 无界面。
- BPMN、Demo、SkyWalking 等脚手架残留，菜单会偏杂。

## 7. 本地启动要点（不代装依赖）

环境：JDK 17、MySQL 8、Redis 6+、Node 16+、Maven 3.8+。后台建议 pnpm ≥ 8.6。C 端用 HBuilderX。

1. 建库并导入 `yshop-drink-boot3/sql/yixiang-drink-open.sql`。
2. 改 `yshop-server` 的 `application-local.yaml`：库 `yixiang-drink-open`，默认 `root/root`，端口 **48081**，Redis `127.0.0.1:6379`。
3. 后端：`mvn clean install package -Dmaven.test.skip=true`，再启动 `yshop-server`。
4. 后台：`yshop-drink-vue3` 执行 `pnpm install`。  
   - `npm run dev` 走默认 mode；`dev-server` 走 `.env.dev`，当前指向远程 `https://apidc.dayouqiantu.cn/admin-api`。  
   - 若要打本地后端，需把 `VITE_BASE_URL` 改成 `http://localhost:48081`。
5. 小程序：HBuilderX 打开 `yshop-drink-uniapp-vue3`，`config/index.js` 开发环境已是 `http://localhost:48081/app-api`。改 `manifest.json` 里的小程序 AppId。

租户默认关闭，验证码后台默认开。短信测试码在配置里固定为 `9999`（`yshop.sms-code`）。

## 8. 给后续「软件兼职平台」改造用的对照

当前领域模型是 **门店 → 商品 SKU → 购物车 → 餐饮订单 → 支付 / 出餐**。兼职平台通常是 **需求方 / 接单方 → 任务 / 职位 → 报名或接单 → 交付 / 结算**。下面按「能留 / 要换语义 / 建议丢掉」分组，方便你出改动计划时对照。

### 8.1 可直接留（平台骨架）

- 后台 RBAC、菜单动态路由、字典、日志、文件上传、短信、租户开关
- C 端登录（短信 / 微信）、个人资料、协议页、地址（若兼职含上门可复用）
- 支付商户配置、微信生态（若仍走小程序）
- 素材库、公告、站内信

### 8.2 建议换语义、少改结构

| 现在 | 兼职平台可映射成 |
|------|------------------|
| 门店 | 企业 / 雇主 / 任务发布方 |
| 商品分类 + SKU | 任务类目 + 技能标签 / 报价档 |
| 点餐菜单 | 任务大厅 / 职位列表 |
| 购物车 + 下单 | 报名 / 接单（通常一单一任务，购物车可能多余） |
| 餐饮订单 | 任务订单（待接单 / 进行中 / 待验收 / 已结算） |
| 优惠券 | 新人券 / 平台补贴（可选） |
| 积分商城 | 可改成信用分、勋章或直接删 |
| 会员余额 | 钱包 / 保证金 / 结算账户 |
| 出餐工作台 | 运营审核台 / 争议处理台 |
| 外卖地址 | 若任务有线下地点可留，否则改成工作地点 |

### 8.3 建议整段去掉或重写

- 自取时间档、取餐号、制作中 / 请取餐状态机
- 堂食 `desk`、云打印、充值套餐（除非要做钱包充值）
- 饮品规格弹窗（杯型 / 温度 / 甜度）——兼职需要的是技能、工期、报价，不是 SKU 加料
- 积分兑周边、快递发货（除非做实物激励）
- README / 首页文案里的「奈雪券」「点餐外卖」等品牌残留

### 8.4 兼职平台几乎肯定要新做的

- 双角色（发任务 / 接任务）或企业 + 个人
- 任务发布、报名、选人、交付物、验收
- 评价与信用（现有商品评价对不上）
- 结算与抽成（现有订单金额模型偏「商品单价 × 数量」）
- 若用于作品集：演示数据、去商业版提示、去官方 AppId / 远程 API 依赖

## 9. 结论

开源 **yshop-drink** 是一套能演示的 **多门店自取 + 外卖** 全栈项目：小程序点餐闭环、后台商品 / 订单 / 会员 / 券、微信登录支付都在。堂食扫码、预约、云打印、充值、装修是宣传大于实现。

作为兼职平台展示项目，价值在 **三端工程与权限 / 支付 / 会员骨架**，不在餐饮业务本身。下一步等你的改动计划后，可以按模块（信息架构 → 数据模型 → C 端页面 → 后台菜单 → 订单状态机）逐项替换，而不是先大面积改样式。
